Recursos

O que o sistema faz

Importação da planilha

Envie o arquivo .xlsx, .xls, .csv ou .ods. O sistema reconhece as colunas do modelo (e variações de nome), avisa sobre linhas com problema e deixa você escolher os itens.

Proposta de licitação

Órgão, UASG, modalidade (lista com opção de criar a sua), pregão, objeto e prazo; dados do proponente com CNPJ, inscrição estadual, SIMPLES NACIONAL, banco e PIX; tabela de preços com marca/modelo e unidade — tudo em Times New Roman.

Orçamento comercial

Mesma estrutura, com identificação do cliente, validade da proposta, condições de pagamento, prazo de entrega e garantia.

Catálogo com fotos

Uma página de catálogo com a descrição comercial e a foto de cada produto — por link (inclusive Google Drive, baixado na hora de gerar) ou enviando a imagem do computador (.jpg ou .png; no modo local GIF e WebP entram convertidos). Foto que não puder ser lida sai como —, o sistema avisa qual item ficou sem foto e o PDF nunca deixa de ser gerado por causa de uma imagem.

Cálculos e margem

Preço de custo e de venda por item, lucro estimado e aplicação de margem em lote. O total sai em números e por extenso.

Banco na nuvem (Supabase ou Firebase)

Com servidor, a empresa e as propostas podem ficar num banco na nuvem — Postgres do Supabase ou Firestore do Firebase (o sistema escolhe pelo que você configurar, e dá para ligar pela própria tela, sem terminal): os dados sobrevivem a atualização, reinício e troca de servidor — e, se o banco cair, o sistema continua no ar com uma cópia local até ele voltar. A chave de acesso fica só no servidor: o site publicado nunca recebe credencial do banco.

Conta para abrir em outro computador

No endereço do GitHub Pages não existe servidor — e aí os dados ficam no navegador. Criando uma conta (e-mail e senha) eles passam a ser guardados no seu projeto Supabase, e você abre o sistema em qualquer computador entrando com o mesmo e-mail e a mesma senha. Tudo sai cifrado do navegador (AES-256, chave derivada da senha): no banco só existe texto cifrado, e a senha não é enviada para lugar nenhum. Sem conta também dá: clique em continuar sem conta e os dados ficam só neste navegador.

Histórico e numeração

Numeração automática (001/2026), status de rascunho a ganha/perdida, busca, filtros, duplicar, excluir e exportar os itens de volta para planilha — ou gerar a planilha auxiliar do documento (itens no formato do modelo + aba de resumo).

Sem senha obrigatória

Nada de senha para usar o sistema no seu computador: ele abre direto no painel. A conta (e-mail e senha) é opcional e serve para levar os dados de um computador para o outro. A empresa é cadastrada uma única vez em Minha empresa — com razão social, CNPJ, inscrição estadual, endereço, logo e assinatura — e esses dados entram no cabeçalho de todos os documentos.

Botão Gerar PDF

Declarações à parte: a seção Declarações, no painel, guarda a Declaração Unificada, a de ME/EPP/MEI e os seus próprios textos (com os dados da empresa trocados automaticamente) — e cada documento escolhe quais saem. O botão Imprimir gera a folha no mesmo padrão da proposta, com o timbre da empresa, pronta para assinar.

Um clique gera o arquivo com cabeçalho, logo, numeração de páginas e o nome pronto (Proposta_001-2026_orgao.pdf), com pré-visualização na tela antes de baixar. O botão Pré-visualização, no topo do editor, oculta ou mostra esse quadro quando você quiser mais espaço para preencher.

Publicação

Como colocar no ar

São dois caminhos. Modo local (GitHub Pages): o endereço já abre o sistema e roda tudo no navegador — ótimo para uso individual, sem instalar nada. Com servidor: sem login, os documentos ficam guardados no servidor (no banco na nuvem ou num arquivo) e podem ser abertos de qualquer computador — proteja o endereço no proxy ou na plataforma de hospedagem. O repositório já vem com render.yaml, railway.json, Procfile e Dockerfile para isso.

1

Use agora, sem instalar nada

O endereço do GitHub Pages abre o sistema em modo local: importe a planilha, gere o PDF e baixe o backup. Os documentos ficam salvos neste navegador.

Abrir o sistema
2

Crie o serviço no Render

Entre em render.com, conecte o GitHub e escolha New + → Blueprint apontando para o repositório licitapro. O resto é lido do render.yaml.

Publicar no Render
3

Proteja o endereço

Não há login: quem abre a URL usa o sistema. Se o serviço ficar na internet, ponha uma senha na frente (proxy, túnel ou a própria hospedagem) ou deixe o acesso restrito à sua rede.

4

Use e faça backup

Acesse a URL gerada, cadastre a sua empresa, importe a planilha e gere o PDF. Guarde a pasta de dados (/var/data ou data/) — nela ficam o banco, os uploads e o cache.

Outras opções: Railway (com volume em /var/data), uma VPS com docker run ou npm start com PM2, ou ainda rodar na sua máquina e expor por túnel temporário. O passo a passo completo está no README.

Sobre os dados: em planos gratuitos o disco costuma ser apagado a cada reinício — ótimo para testar, mas para uso real prefira um disco persistente ou uma VPS.

Uso local

Rodar na sua máquina

git clone https://github.com/marcossilva023l20/licitapro.git
cd licitapro
npm install
npm start          # abre em http://localhost:3000

npm run testes     # 78 testes automatizados
npm run paginas    # regenera o index.html do GitHub Pages
npm run fontes     # regenera as métricas da fonte Times
npm run modelo     # gera a planilha-modelo (.xlsx)
npm run banco -- configurar   # grava as credenciais do banco (opcional)

# ...ou, com o sistema aberto em localhost, use o botão
# "Conectar banco de dados" no painel: grava e testa na hora

Na primeira execução o sistema cria apenas o perfil (dados da empresa), na pasta data/ — não há usuário nem senha para configurar.
